# Self-review

## Принятые решения

1. **Ключ и состояние сохраняются до POST, а после перезапуска файл сам не отправляется.** В `import-op.json` лежат ключ идемпотентности, jobId, ревизия и ключ удаления. Если отправка оборвалась или приложение убили, состояние становится «результат неизвестен»: приложение только делает `GET /imports/by-key/…`. Повторный POST (тот же ключ, те же байты) возможен только по нажатию пользователя. Цена: лишний тап в редком случае. Выгода: второй job невозможен.
2. **Правда о статусах решается ревизиями, а не порядком ответов.** `mergeStatus` игнорирует ответ со старой ревизией, а после принятого удаления игнорирует всё, кроме `deleting`/`deleted`. Слово «удалено» показывается только при `deleted` от сервера, 503 оставляет job на экране с ключом удаления для повтора.
3. **Проверка файла по содержимому и без загрузки в память.** Размер из picker и `stat`, первые 32 байта через `fs.slice`, формат определяется по сигнатуре, как у сервера. Загрузка потоком с диска (`react-native-blob-util`). Копия в приватном кеше удаляется при создании job, отказе, отмене и «Discard».

## Что упростил ради срока

- Нет очистки «осиротевших» копий при старте: если приложение убить между выбором файла и подтверждением, копия останется в кеше до очистки системой.
- Опрос раз в секунду без backoff, один активный импорт, ключ из `Math.random` (для идемпотентности достаточно, для безопасности нет).
- Состояние пишется обычным `writeFile`, без атомарной замены.
- Отдельного экрана диагностики нет: счётчики мока смотрю командами из README.
- Крупный системный шрифт и маленький экран вручную не проверял.

## Что сломается первым в production

- Сервер ответил 404 на известный job (например, сброс мока): приложение покажет «Connection problem», кнопки «убрать job» нет. Заметно по повторяющейся плашке и жалобам на «зависший» импорт.
- Автоповтор POST внутри HTTP-клиента Android: на lost_ack `createRequests=2`, `duplicateHits=1`, `newJobs=1`. Безопасно из-за ключа, но запросов больше, чем отправок. Заметить: рост `duplicateHits` относительно `newJobs`.
- Cleartext HTTP работает только в debug-сборке. Release потребует HTTPS.
- Провайдеры файлов, которые не сообщают размер: копия сначала делается целиком, потом проверяется.
